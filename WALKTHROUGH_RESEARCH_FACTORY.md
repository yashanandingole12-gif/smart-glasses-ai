# Wearable Context Factory Research Walkthrough

This walkthrough explains how to run the synthetic vehicle-factory experiment, use the realtime Streamlit dashboard, inspect SQLite data, and interpret the results.

All worker, wearable, robot, and factory measurements generated by this project are **synthetic/simulated data**. They are not measurements from human participants, a real factory, or a medical device.

## 5. Understand the dashboard

### 5.1 Experiment controls

The sidebar contains:

- **Context condition:** chooses the baseline or wearable modality
- **Scenario injection:** introduces normal or abnormal factory behavior
- **Random seed:** controls reproducibility
- **Initialize run:** creates a new factory state
- **Start / step realtime cycle:** advances one event-loop cycle
- **Run 30-cycle periodic analysis:** generates and persists 30 cycles

The dashboard is query-driven. A cycle is not generated until you click a control button.

## 6. Run a realtime cycle

1. Select `full` under **Context condition**.
2. Select `normal` under **Scenario injection**.
3. Keep the random seed at `42`.
4. Click **Initialize run**.
5. Click **Start / step realtime cycle**.

One cycle generates events for the ten departments:

1. Raw Logistics
2. Body Shop
3. Welding
4. Painting
5. Powertrain
6. Battery Electrical
7. General Assembly
8. Quality Inspection
9. Testing
10. Finished Dispatch

The system then:

1. Generates synthetic wearable telemetry.
2. Updates worker state.
3. Updates machine and robot state.
4. Calculates context confidence.
5. Applies the HMI/HRI policy.
6. Moves the vehicle through the factory.
7. Writes records to SQLite.
8. Refreshes the dashboard state.

The factory layout image is shown in the main floor section. The interactive Plotly state map below it shows station status, workers, robots, risk, and vehicle position.

## 7. Test the baseline condition

To run the baseline:

1. Select context condition `none`.
2. Select scenario `normal`.
3. Click **Initialize run**.
4. Click **Run 30-cycle periodic analysis**.

In this mode, the policy does not use wearable-derived worker context. It still has machine and environmental state.

This condition answers:

> What happens when the system operates without wearable-derived human context?

## 11. Useful SQL queries

Run these from the SQL query runner.

### Count telemetry records

```sql
SELECT COUNT(*) AS telemetry_rows
FROM wearable_telemetry;
```

### Mean fatigue by department

```sql
SELECT
    wt.department,
    AVG(ws.fatigue_index) AS mean_fatigue,
    AVG(ws.context_confidence) AS mean_confidence
FROM worker_state AS ws
JOIN wearable_telemetry AS wt
    ON wt.run_id = ws.run_id
    AND wt.cycle = ws.cycle
    AND wt.worker_id = ws.worker_id
GROUP BY wt.department;
```

### Robot actions

```sql
SELECT
    robot_action,
    COUNT(*) AS action_count
FROM context_events
GROUP BY robot_action
ORDER BY action_count DESC;
```

### Packet loss

```sql
SELECT
    scenario,
    SUM(packet_lost) AS lost_packets,
    COUNT(*) AS total_packets,
    CAST(SUM(packet_lost) AS REAL) / COUNT(*) AS packet_loss_rate
FROM wearable_telemetry
GROUP BY scenario;
```

### Safety events by department

```sql
SELECT
    department,
    event,
    COUNT(*) AS count
FROM safety_events
GROUP BY department, event
ORDER BY count DESC;
```

### Latest factory states

```sql
SELECT *
FROM factory_state
ORDER BY id DESC
LIMIT 20;
```

## 13. Interpret results correctly

The simulation can demonstrate:

- data generation
- event streaming logic
- database persistence
- robot adaptation rules
- context confidence behavior
- failure handling
- baseline versus ablation comparisons

The simulation cannot prove:

- that a wearable accurately diagnoses fatigue
- that physiological data reveals intention
- that a real factory will become more productive
- that a commercial smart-glasses device is safe for every task
- that the context score is clinically or scientifically validated

Use phrases such as:

- synthetic result
- simulated observation
- proposed metric
- experimental protocol
- expected evaluation

Avoid presenting synthetic data as human-subject or industrial field data.

## 16. Recommended demonstration sequence

For a short presentation:

1. Start the dashboard.
2. Show the static factory layout.
3. Select `none` and run 10 cycles.
4. Select `full` and run 10 cycles.
5. Compare robot actions and context confidence.
6. Select `packet_loss` and run 10 cycles.
7. Show the confidence reduction and fallback behavior.
8. Open the SQL query runner.
9. Run the department fatigue query.
10. Open the smart-glasses concept tab.
11. Explain that every measurement is synthetic.
12. Close with the research question: when does wearable context justify its operational and privacy cost?
